# 1대1 사격 MVP 검증 기록

2026-11-20 기준. `Scenes/ShootingTrial1v1.unity`에 고정된 캡슐 두 개와 엄폐물이 있다. 플레이어와 시험 상대는 같은 사격 코드를 사용한다. 상대의 반격은 기본으로 꺼져 있다.

## 시험 씬 조작

Unity에서 씬을 열고 Play를 누른 뒤 Game 뷰에서 조작한다.

| 입력 | 동작 |
|---|---|
| Space 또는 마우스 왼쪽 유지 | 플레이어 발사 요청 |
| A / D, Q / E | 시험용 좌우 이동, 몸체 회전 |
| C | 서기·앉기 전환 |
| 1 / 2 / 3 | 개방 / 오른쪽 총구만 가리는 낮은 엄폐 / 시야까지 가리는 높은 엄폐 |
| B | 상대의 스크립트 발사 명령 켜기·끄기 |
| R | 고정 스폰·체력·조준·쿨다운 초기화. 양측 시드 731·732로 재시작 |

시작 위치에서 1번은 직접 사격, 2번은 표적이 보일 때의 총구 차폐, 3번은 표적 상실을 확인하는 조건이다. 화면에서 양측 체력과 마지막 사격 결과를 볼 수 있다. 시험 체력이 소진되면 라운드를 멈춘다.

| 발사 간격 | 실제 사격 시계 코드에 0.02초 간격으로 같은 틱을 두 번씩 전달했다. [0, 1)초에 쏠 수 있는 시점은 0.0·0.2·0.4·0.6·0.8초, 총 5회였다. 역행·비정상 시간 거부와 리셋 직후 대기 해제도 확인했다. |

| 씬 배치 | 직렬화된 객체·컴포넌트 83개의 로컬 참조를 확인했다. 시작 위치에서 눈 (0, 1.82, −5)과 오른쪽 총구 (0.48, 1.24, −4.54)에서 몸통 (0, 1, 5)까지 선분과 엄폐 상자의 교차를 계산했다. 개방에서는 둘 다 통과, 낮은 엄폐에서는 총구만 차단, 높은 엄폐에서는 둘 다 차단됐다. |

Unity Test Runner의 EditMode에서 `Reinforcement.Shooting.EditMode` 어셈블리를 선택하면 실제 캡슐 사격 10,000회, 최초 충돌과 피해 1회, 복합 충돌체, 근접 차폐, 머리·몸통, 자세·초기화, 읽기 전용 질의 등을 재현할 수 있다. 제안한 통제 시험 인수 범위는 실제 10,000발 중 6,800~7,200회 명중, 거부 0회다. Play 모드의 수동 조작은 아직 검증하지 않았다.

## 팀 연결 API · 2026-11-24

이승재의 `ShootingWeapon`이 오토에임과 **선택된 표적 정보**를 함께 제공한다. 현재 관측 후보는 시험용 `TrialVision`이 만든다. 운영용 공통 시야 공급자 담당자는 팀에서 정해야 한다. 담당자가 정해지면 같은 경기·틱의 관측 후보와 실제 수평 탐지 거리(m)를 `new VisibilityFrame(episodeId, tick, candidates, maxDetectionDistance)`로 전달한다. 후보 3인자 생성자는 기존 100m 시험 조건을 사용한다.

### 조회

`Tick` 처리 후 `var state = weapon.GetState();`로 한 번에 읽는다. 조준점은 오토에임에서 사용한 위치의 복사본이다.

| `ShootingState` 필드 | 의미 |
|---|---|
| `HasTarget`, `TargetId`, `AimPoint` | 유효 표적 여부, 표적 ID, 몸통 중심 월드 좌표. 표적이 없으면 `false`, `-1`, `Vector3.zero` |
| `TargetUpdateTick` | 표적 선택 또는 상실을 마지막으로 처리한 시뮬레이션 틱. 초기화·종료 직후는 `-1` |
| `MaxDetectionDistance` | 시야 공급자가 마지막 유효 프레임에 전달한 양수 수평 거리(m). 첫 프레임 전 기본값은 100이며, 해당 경기의 값은 `IsReady`가 참일 때 사용 |
| `IsReady` | 경기가 활성이고 발사자가 생존하며 무기 참조·설정과 현재 틱의 시야 입력이 유효함. 후보가 0명이어도 준비 상태일 수 있음 |
| `CanFire` | 현재 처리한 틱에서 표적·대기 시간·총구 조건상 발사 요청을 받을 수 있음. 총구 앞의 벽에 막히는 사격도 실제 발사로 처리 |
| `Origin`, `EffectiveRange` | 오른쪽 총구의 현재 월드 위치와 유효 사거리(m) |

**MVP 실행 규칙**. 시야 밖이나 엄폐 뒤로 사라진 표적은 다음 관측 틱에 해제하며 무표적 발사를 거부한다. 눈에서 몸통 중심을 향한 첫 유효 충돌이 해당 적이어야 보인다. 머리만 노출되어 이 선이 벽에 막히면 미탐지다. 살아 있는 적 중 총구 사거리 안에서 눈과 관측점의 3차원 거리가 가장 짧은 대상을 고르고, 동거리면 작은 캐릭터 ID를 고른다. 이동 측이 몸체 방향을 결정하고 사격은 총구 피벗만 회전한다. 수치와 운영 환경에서 합의할 항목은 아래 표에 있다.

### 입력·초기화

1. 경기 시작 시 `ResetEpisode(newEpisodeId)`를 호출한다. 경기·발사자 ID로 사격 전용 시드를 만든다. 재현 실험은 기존 `ResetEpisode(newEpisodeId, seed)`로 시드를 지정한다. 초기화하면 표적·쿨다운·유지 명령·최근 결과·경기 내 순번을 지운다. 즉시 판정 방식이므로 정리할 비행 중 탄환이나 탄창은 없다.
2. 이동·자세 및 물리 상태를 반영한 후 같은 틱의 시야를 수집한다. 입력 소유자가 `SetCommand(bool fireHeld)`로 요청을 유지·해제하고, `Tick(episodeId, tick, simulationTime, frame)`에 경기 공통 시계(초)를 전달한다. 이전 경기의 지연 입력이 가능하면 `SetCommand(episodeId, fireHeld)`를 사용한다. 명령을 반복해도 같은 틱이나 쿨다운 중에는 추가 발사가 발생하지 않는다.
3. `EndEpisode()`로 종료한다. 사망·종료 상태에서는 발사를 차단한다.

### 발사·명중 사건

| 이벤트 | 전달값과 발생 조건 |
|---|---|
| `ShotFired(ShotFiredEvent e)` | 실제 발사당 1회. `e.EpisodeId`, `e.ShotId`(long), `e.ShooterId`, `e.FiredAt`(공통 시계의 초), `e.SelectedTargetId`. 현재는 무표적 발사를 거부하므로 통지된 발사에는 선택 표적이 있다. |
| `ShotHit(ShotHitEvent e)` | 최초 유효 충돌체가 캐릭터일 때 최대 1회. `e.Shot`은 위 발사 정보의 복사본이다. `e.HitTargetId`, `e.HitAt`, `e.Region`은 실제 충돌 결과다. 먼저 맞은 다른 적·아군도 해당 ID로 통지한다. 아군 시험 피해는 0이다. 벽·빗나감에는 명중 통지가 없다. |

사격 시스템은 실제 발사를 확정할 때 `ShotId`를 발급한다. 중복 식별 키는 `(EpisodeId, ShooterId, ShotId)`다. `ShooterId`는 경기 측이 연결한 `ShotActor.ActorId`에서 받고, 발사와 명중·피해 요청에 같은 키를 사용한다. 즉시 판정이므로 발사와 명중의 시각은 같고 발사 통지 후 명중을 통지한다. 예를 들어 42번 경기의 발사 처리 중 구독자가 43번 경기를 시작해도 명중은 보관한 42번 ID와 시각으로 전달된다. 피격 부위는 현재 캡슐의 상단 1/7 이상을 `Head`, 나머지를 `Body`, 분류할 캡슐이 없으면 `None`으로 기록한다.

기존 `ShotResolved`는 평가용 상세 결과(최초 충돌·부위·실제 피해·사망)를 계속 전달한다. 이벤트 구독은 경기 간 유지된다. `QueryShotLine`은 피해 없는 차폐 조회다. 팀 공통 경기·시야·PPO와의 실연결은 대기 중이다.

### 11월 24일 검증 결과

설치된 Unity 6000.3.28f1 참조로 런타임·시험 씬 코드·EditMode 테스트 어셈블리를 경고를 오류로 처리하여 컴파일했다. 사격의 실제 이벤트 통지 코드를 독립 실행해 발사→명중 순서, 42→43 경기 변경 시 원래 발사 키 보존, 선택 대상과 실제 피격자 구분, 미명중 시 발사 통지만 발생, 미구분 부위 전달을 확인했다. 시야 프레임의 사용자 지정 거리와 기존 기본 거리도 확인했다.

Unity MCP를 연결해 EditMode 테스트 19개를 실행했고 모두 통과했다. 실제 물리 충돌을 포함한 단일 노출 표적 시험은 시드 20261120에서 발사 10,000회, 표적 명중 6,969회(69.69%), 거부 0회, 빗나감 방향 생성 실패 0회였다. 시험 준비 과정에서 발견한 임시 씬 생성 및 Editor 전용 피격자 문제를 수정한 뒤 재실행했다. Unity가 프로젝트 외부에 생성한 테스트 결과 XML은 통과 내역을 확인한 후 삭제했다. Play 모드 수동 조작과 팀 시스템 연결은 미검증이다.
