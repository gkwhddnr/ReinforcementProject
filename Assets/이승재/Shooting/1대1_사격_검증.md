# 1대1 사격 MVP 검증 기록

2026-11-20 기준. `Scenes/ShootingTrial1v1.unity`에 고정된 캡슐 두 개와 엄폐물이 있다. 플레이어와 시험 상대는 같은 사격 코드를 사용한다. 상대의 반격은 기본으로 꺼져 있다.

## 시험 씬 조작

Unity에서 씬을 열고 Play를 누른 뒤 Game 뷰에서 조작한다.

| 입력 | 동작 |
|---|---|
| Space 또는 마우스 왼쪽 유지 | 플레이어 발사 요청 |
| A / D, Q / E | 시험용 좌우 이동, 몸체 회전 |
| C | 서기·앉기 전환 |
| 1 / 2 / 3 | 개방 / 오른쪽 총구만 가리는 낮은 엄폐 / 시야까지 가리는 높은 엄폐 |
| B | 상대의 스크립트 발사 명령 켜기·끄기 |
| R | 고정 스폰·체력·조준·쿨다운 초기화. 양측 시드 731·732로 재시작 |

시작 위치에서 1번은 직접 사격, 2번은 표적이 보일 때의 총구 차폐, 3번은 표적 상실을 확인하는 조건이다. 화면에서 양측 체력과 마지막 사격 결과를 볼 수 있다. 시험 체력이 소진되면 라운드를 멈춘다.

## 수행한 검증

| 대상 | 방법과 결과 |
|---|---|
| Unity MCP | 로컬 HTTP 서버 10.3.0에서 인스턴스 1개, 프로젝트 경로 `D:/Rein/ReinforcementProject`, 에디터 버전 `6000.3.28f1`을 읽었다. |
| 컴파일 | 설치된 동일 버전 Unity의 Roslyn과 프로젝트 패키지 참조로 런타임, 시험 씬 코드, EditMode 테스트 어셈블리 3개를 각각 컴파일했다. |
| 발사 간격 | 실제 사격 시계 코드에 0.02초 간격으로 같은 틱을 두 번씩 전달했다. [0, 1)초에 쏠 수 있는 시점은 0.0·0.2·0.4·0.6·0.8초, 총 5회였다. 역행·비정상 시간 거부와 리셋 직후 대기 해제도 확인했다. |
| 70% 확률 분기 | 시드 20261120에서 독립 난수 10,000개를 실제 분기 함수에 전달해 6,992개가 조준 방향으로 분류됐다. 0·0.6999·0.7 및 강제 명중·빗나감 경계도 확인했다. 물리 충돌을 포함한 명중률은 별도 시험 대상이다. |
| 씬 배치 | 직렬화된 객체·컴포넌트 83개의 로컬 참조를 확인했다. 시작 위치에서 눈 (0, 1.82, −5)과 오른쪽 총구 (0.48, 1.24, −4.54)에서 몸통 (0, 1, 5)까지 선분과 엄폐 상자의 교차를 계산했다. 개방에서는 둘 다 통과, 낮은 엄폐에서는 총구만 차단, 높은 엄폐에서는 둘 다 차단됐다. |

**Unity 물리·Play 모드 실행은 미검증이다.** 현재 MCP 테스트 러너에는 담당 폴더 밖에 결과 파일을 기록하는 콜백이 있다. 이번 작업의 검증 범위는 담당 폴더 내부다. `Tests/ShootingMvpTests.cs`의 EditMode 테스트 16개에는 시드 20261120의 실제 캡슐 사격 10,000회, 최초 충돌과 피해 1회, 복합 충돌체, 근접 차폐, 머리·몸통, 자세·초기화, 읽기 전용 질의의 RNG 보존이 포함된다. Unity Test Runner의 EditMode에서 `Reinforcement.Shooting.EditMode` 어셈블리를 선택하면 이 시험들을 재현할 수 있다. 통제 시험은 실제 발사 수·선택 표적 명중 수·거부 수·빗나감 방향 생성 실패 수를 출력한다. 제안한 인수 범위는 실제 10,000발 중 6,800~7,200회 명중, 거부 0회다.

## 팀 연결 지점

- **입력과 시야**. 경기 시작 시 각 무기에 `ResetEpisode(episodeId, seed)`를 호출한다. 몸체와 자세를 갱신하고 물리 상태를 반영한 뒤, 현재 틱에서 관측한 상대만 `VisibilityFrame`에 담는다. `SetCommand(episodeId, fireHeld)`로 하나의 입력 소유자가 발사 여부를 정하고 `Tick(episodeId, tick, simulationTime, frame)`을 호출한다. 시야는 같은 경기·같은 틱에서만 유효하다. 경기 종료는 `EndEpisode()`로 전달한다.
- **체력과 평가**. 캐릭터 어댑터 `ShotActor`는 ID·팀·생존과 실제 피해 수신 결과를 제공한다. `ShotResolved`에는 겨냥한 대상 ID와 실제 피격자 ID, 최초 충돌, 피격 부위, 실제 적용량·사망 여부가 담긴다. `QueryShotLine`은 총구 차폐·사거리 초과 여부와 시뮬레이션 시각을 반환한다. 원시 사건은 평가용이며 정책 관측 스키마는 학습 담당이 정한다.
- **현재 연결 수준**. 이동·시야·체력·상대 행동·라운드 종료는 담당 폴더의 시험 코드다. 팀 캐릭터·공통 체력/경기 API·랜드스케이프·PPO와의 통합, 3대3 및 MA-POCA는 후속 단계다. 시험 씬은 한 틱에 플레이어를 먼저 처리한다. 동시 피격·승패 규칙은 경기 담당과 정한다.

## 시험값과 합의할 사항

| 항목 | 현재 시험 규칙 | 확정할 사항 |
|---|---|---|
| 시야 | 한 변 50 × 두 청크의 수평 직선거리 100 이하, 수평 시야각 90° | 맵의 청크 정보, 격자·대각선 해석, 시야 갱신 주기 |
| 조준·발사 | 무기 피벗만 회전. 사거리 20, 간격 0.2초, 표시선 0.05초. 표적이 없으면 거부 | 몸체 회전 소유자, 사거리·간격, 입력 유지·미탐지 규칙 |
| 피격·체력 | 캡슐 상단 1/7을 머리로 분류. 서기 2.0·앉기 1.2, 체력 100, 양 부위 시험 피해 20 | 실제 자세·충돌체, 경계, 피해량·배율, 사망·리셋 소유자 |
| 차폐·팀전 | 자기 충돌체와 트리거 제외. 아군 충돌 시 차단하고 피해 0. 총구가 다른 캐릭터와 겹치면 거부 | 공용 레이어·엄폐 ID, 아군 피해, 표적 우선순위와 평가·보상 계약 |
