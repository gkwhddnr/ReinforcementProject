# 1대1 강화학습 연결 뼈대

Unity 6000.3.28f1, ML-Agents 4.2.0을 기준으로 한다. 브랜치는 `feature/learning`이며 Decision과 Training 안에서 조원 기능을 연결할 진입점을 제공한다. 현재 게임 환경의 이동·회전·시야·오토에임·피해·물리 판정은 각 담당자의 구현을 연결해야 한다.

## 구성

- `ObservationFrame`은 담당 시스템의 원래 값을 받아 10개 관측으로 정규화한다.
- `DecisionAction`은 이산 행동 `[5, 3, 2]`를 이동 벡터·회전 방향·발사 요청으로 바꾼다.
- `LearningBridge`를 상속한 컴포넌트를 학습 연결 계층에 구현하여 조원 시스템을 호출한다. 필수 연결이 준비되면 `IsReady`가 참이 된다. 학습 코드에서 게임 물리를 다시 구현하지 않는다.
- `DecisionAgent`는 관측과 행동을 ML-Agents에 연결한다. 결정 주기의 시작값은 Academy 5스텝이다. 중간 스텝에는 마지막 행동을 반복한다.
- `MatchEpisodeController`는 두 참가자의 준비·종료·보상·중단을 조정한다. `DuelEpisode`는 Unity 시간과 독립적으로 300초 제한 및 결과 정산을 계산한다.

## 나중에 연결할 API

| API | 연결 담당과 의미 |
| --- | --- |
| `LearningBridge.IsReady` | 필수 이동·사격·시야·체력·스폰 참조를 확인한다. 미연결을 정상 미탐지로 처리하지 않는다. |
| `TryReadObservation(out frame)` | 체력·수평 속도·엄폐 거리·유효 표적 정보를 같은 시점 기준으로 읽는다. 값을 못 읽으면 false를 반환한다. |
| `ApplyAction(action)` | `Move`는 캐릭터 기준 X 좌우·Y 전후다. `Turn`은 -1 좌회전·0 유지·1 우회전이다. 조원과 합의한 각도 또는 각속도 의미로 변환한다. `Fire`는 발사 요청이다. 기본값은 모든 입력 해제로 처리하고, 정지 명령은 의존성이 준비되지 않은 경우에도 안전하게 처리한다. |
| `ResetForEpisode(episodeId)` | 지정된 스폰으로 복원하고 체력·속도·자세·입력·발사 대기와 과거 사건을 초기화한다. 두 참가자의 공통 맵 초기화는 경기 소유자가 한 번 조정한다. 현재 시그니처는 동기식 준비 완료를 전제로 한다. |
| `MatchEpisodeController.Bind(first, second)` | 서로 다른 두 Agent를 지정한다. Inspector 참조를 사용해도 된다. |
| `StartMatch()` | Play 진입 후 Academy의 첫 에피소드 초기화가 끝난 시점에 경기 소유자가 호출한다. 두 브릿지 준비와 관측 검증을 통과해야 시작된다. 실패하면 false이며 중단 상태로 남는다. |
| `ReportDefeat(episodeId, participant)` | 체력 시스템의 확정 탈락을 전달한다. 참가자 0은 첫 Agent, 1은 두 번째 Agent다. 이전 경기 사건은 거부한다. |
| `CompleteSimulationStep(delta)` | 물리·사격·피해와 양쪽 탈락 사건을 모두 처리한 뒤 경기 소유자가 스텝당 한 번 호출한다. delta는 배속을 반영한 시뮬레이션 경과 시간이다. 현재 뼈대에는 자동 FixedUpdate 타이머가 없다. |
| `QueueTerminalBonus(episodeId, participant, eventId, amount)` | 계산식이 합의된 부가 점수만 입력한다. 같은 참가자·경기·eventId의 중복 지급은 거부한다. 합산은 종료 시 한 번 보상에 반영한다. |
| `EpisodeFinished` | 불변 결과 스냅샷을 평가 집계·기록 시스템에 제공한다. 다음 경기를 시작할 시점도 경기 소유자가 결정한다. 구독자는 비활성화·씬 종료 시 구독을 해제한다. |

이동 담당의 기존 `PlayerAgentInputBridge.SetActionsFromAgent`와 연결할 수 있다. 실제 이동 방향이 관전 카메라에 종속되지 않는지, 이동 중과 제자리에서 회전이 같은 규칙을 따르는지 통합 때 확인한다. 표적을 놓쳤을 때 발사를 허용할지는 사격 담당과 확정하고 해당 브릿지·사격 코드에 일관되게 적용한다.

## 담당자 전달용 임시 연결 규격 v0

2026년 11월 21일 학습 연결 제안이다. 팀 검토 후 확정하며, 기존 조원 API의 이름과 자료형은 학습 쪽 연결부에서 변환할 수 있다. 아래 표의 필드명과 사건은 요청 규격이며, 각 담당 시스템이 실제 제공하는지 통합 전에 확인한다.

현재 상태는 학습 쪽에서 필요한 시점에 조회한다. 실제 발사·피해·탈락은 발생 시 사건으로 전달한다. 원래 단위의 값을 제공받고 정규화·교전 판정·평가 집계와 보상 계산은 Training에서 수행한다.

| 담당 | 학습 쪽에서 조회할 값 | 학습 쪽이 전달할 명령 |
| --- | --- | --- |
| 이동 · 이용현 | 월드 위치 `Vector3`, 몸체 회전 `Quaternion`, 현재 속도 `Vector3`, 기준 최대 이동 속도 `float > 0`, 준비 여부 `bool` | 이동 `Vector2`, 회전 방향 `int`, 입력 해제, 경기 ID와 스폰 위치·회전에 따른 리셋 |
| 공통 시야·사격 · 담당 합의 | 유효 표적 여부 `bool`, 선택된 표적 ID `int`, 선택된 표적 조준점의 월드 위치 `Vector3`, 탐지 거리 `float > 0`, 갱신 틱, 발사 가능 여부 `bool` | 발사 유지 `bool`, 입력 해제, 새 경기 ID와 초기화 요청 |
| 체력 · 담당 합의 | 현재 체력 `float`, 최대 체력 `float > 0`, 생존 여부 `bool`, 준비 여부 `bool` | 새 경기의 체력·사건 초기화 요청 |
| 환경 · 하종욱 | 맵·스폰 배치 ID, A/B 스폰 위치·회전, 지정 엄폐물 ID와 충돌 참조, 준비 여부 | 경기에서 사용할 스폰 배치 선택 요청 |
| 엄폐 센서 · 담당 합의 | 몸체 기준 앞·오른쪽·뒤·왼쪽의 원래 거리 `Vector4`와 감지 최대 거리 `float > 0` | 센서 조회. 차단체가 없으면 해당 방향에 감지 최대 거리 반환 |

`LearningBridge`는 위 값을 조합한다. 이동 속도에서 수평 성분의 크기를 구해 `PlanarSpeed`에 넣는다. 선택된 조준점의 월드 위치는 자신의 몸체 기준으로 변환해 `TargetLocalPosition`에 넣는다. 오토에임과 정책 관측은 같은 선택 표적·스냅샷을 사용한다. 표적이 없으면 ID는 -1, 위치는 0을 제공한다. 센서를 못 읽거나 필수 연결이 빠진 경우는 준비 실패로 처리한다.

이동 명령의 X는 왼쪽 -1·오른쪽 +1, Y는 후진 -1·전진 +1이며, 몸체 기준으로 해석한다. 회전 명령은 -1 좌회전·0 유지·+1 우회전이다. 명령은 다음 갱신까지 유지하고 이동 담당이 시뮬레이션 시간에 맞춰 적용한다. 회전은 초당 360도를 시작값으로 제안하며, 제자리에서도 같은 규칙을 적용한다. 이산 회전 선택지 0·1·2는 학습 연결부가 0·-1·+1로 변환하므로 담당자에게는 변환된 방향을 전달한다. 이동 구현이 목표 방향 벡터를 받으면 이 명령을 연결부에서 변환한다.

발사 유지가 false이면 발사 입력을 해제한다. true일 때 발사 간격·생존·차폐·표적 조건의 실행 검사는 사격 담당이 수행한다. 표적이 없는 경우의 발사 허용 규칙은 통합 전에 합의한다. 정책 결정 주기는 Academy 5스텝을 임시값으로 사용하며, 이동·사격 담당이 결정 횟수를 이동 거리나 탄 수로 사용하지 않도록 한다.

| 사건 또는 판정 | 제공할 내용 | 학습 쪽 처리 |
| --- | --- | --- |
| 실제 발사 · 사격 담당 | `episodeId`, 고유한 `shotId`, 시뮬레이션 시각, 발사자 ID, 발사 순간 선택 표적 ID 또는 -1 | 실제 발사 수와 표적 변경 기록. 발사 요청·거절과 구별 |
| 실제 피해 · 체력 담당 | `episodeId`, 고유 사건 ID 또는 `shotId`, 시뮬레이션 시각, 가해자·피해자 ID, 실제 적용 피해량, 최초 탈락 여부 | 실제 피해를 한 번 집계. 사건 ID와 참가자를 사용해 중복 방지 |
| 탈락 · 체력 담당 | `episodeId`, 참가자 ID, 시뮬레이션 시각 | 참가자 ID를 경기 내 0 또는 1로 매핑해 `ReportDefeat` 호출 |
| 평가용 엄폐 차단 · 시야·사격 담당과 합의 | `episodeId`, 판정 시각, 공격자·피보호자 ID, 사거리 내 여부, 첫 차단체 종류와 엄폐물 ID. 상대 시야각과 관계없이 실제 사격선 기준으로 검사 | 유효 교전에서 연속 차단 시간을 누적해 엄폐 교전 인정. 0.1초 확인·0.5초 유지·2초 교전 종료는 팀 검토용 제안값 |

엄폐 차단은 발사를 발생시키지 않는 읽기 전용 판정으로 조회하거나 같은 내용을 주기적으로 제공받는다. 판정 틱이 누락되면 그 구간을 연속 엄폐로 가정하지 않는다. 관측용 네 방향 거리와 상대별 평가용 사격선 차단은 서로 다른 정보다.

학습 경기 ID를 제공자에게 전달하고 이전 경기 사건은 무시한다. 모든 시각은 동일한 경기 시작 기준의 시뮬레이션 초를 사용하며, 명령 유지와 타이머는 배속에 맞게 갱신한다. 갱신·판정 순서는 명령 적용 → 이동·회전 → 시야·오토에임 → 사격·피해 → 평가 사건 → `CompleteSimulationStep(delta)` 순서로 합의한다. 정책은 결정 시점에 제공된 최신 유효 상태를 읽는다. 다음 경기 준비가 끝날 때까지 입력은 해제 상태로 유지한다.

현재 뼈대에 구현된 외부 진입점은 `LearningBridge`와 `MatchEpisodeController`의 API다. 이 표의 발사·피해·엄폐 사건 제공과 최종 집계는 조원 기능이 준비된 뒤 연결한다.

## 관측과 행동 규격

| 인덱스 | 관측 | 값과 누락 처리 |
| --- | --- | --- |
| 0 | 체력 | Health / MaximumHealth, 0~1 |
| 1 | 수평 속도 | PlanarSpeed / MaximumSpeed, 0~1 |
| 2~5 | 앞·오른쪽·뒤·왼쪽 엄폐 거리 | 각 거리 / CoverSensorRange, 0~1. 감지된 차단체가 없으면 제공자가 센서 최대 거리를 전달 |
| 6 | 유효 표적 여부 | 0 또는 1 |
| 7~9 | 캐릭터 기준 표적 위치 | 오른쪽·위·앞 순서, DetectionRange로 나누고 -1~1로 제한. 미탐지 시 0 |

양수 기준값과 유한한 관측만 허용한다. 미탐지 상태에서는 남아 있는 표적 좌표를 읽지 않는다. 발사 가능 상태는 현재 10개 관측에 포함되지 않는다. 추가할 때 배열·Unity 설정·모델 스키마를 함께 변경한다.

이동은 0 정지, 1 전진, 2 후진, 3 왼쪽, 4 오른쪽이다. 회전은 0 유지, 1 좌회전, 2 우회전이며 발사는 0 요청 없음, 1 발사 유지다. 질주·앉기는 첫 행동 스키마에 포함되지 않는다.

## Agent 설정과 검증

1. 참가자 오브젝트에 `BehaviorParameters`, `DecisionAgent`, 향후 구현할 `LearningBridge` 파생 컴포넌트를 연결한다.
2. Play에 들어가기 전에 Behavior Name을 `DuelPPO`, Vector Observation Space Size를 10, Stacked Vectors를 1로 지정한다. 연속 행동은 0개, 이산 분기는 `[5, 3, 2]`로 설정한다.
3. 별도 `DecisionRequester`를 붙이지 않는다. Agent가 실행 중에만 Academy에 결정을 요청한다. 준비·종료 상태에서는 명령을 적용하지 않는다.
4. 최초 동작은 `Heuristic Only`에서 `SetHeuristicAction(movement, rotation, fire)`로 확인한다. 해당 입력도 정책과 같은 `OnActionReceived` 및 브릿지 경로를 통과한다.
5. 두 Agent를 경기 컨트롤러에 지정하고 최초 Academy 초기화 이후 `StartMatch()`를 호출한다. 조원 기능을 실제로 연결한 뒤에 Python 학습과 반복 경기를 검증한다.

Unity Test Runner의 EditMode에서 `Reinforce.Training.Tests`를 실행하면 관측·미탐지·행동 변환, 시간 초과·동시 탈락·부가 보상 중복 방지·새 경기 초기화 및 실제 Agent 진입점 연결을 검증한다. 테스트의 `StubLearningBridge`는 검증용 값을 공급하며 게임 동작이나 학습 성능을 검증하지 않는다.

## 보상과 남은 합의

11월 17일 회의 기준 제한 시간은 시뮬레이션 300초이며 경기 결과 보상은 승리 +1, 패배 -1, 무승부 0이다. 양측이 같은 스텝에 탈락하거나 제한 시간까지 생존하면 무승부로 처리하는 구현 제안이다. `ReportDefeat`를 먼저 모두 전달하고 스텝을 마감해야 같은 스텝 탈락을 함께 판정할 수 있다. 종료 후의 늦은 사건과 점수는 반영하지 않는다.

부가 점수는 아직 정책에 자동 지급하지 않는다. 가한·받은 피해량 0.4의 부호와 계산식, 생존 점수, 무교전 약 -0.1, 첫 교전 점수 0.2, 회복 점수와 명중률 70~80%의 적용 방식은 합의가 필요하다. 실제 피해·교전·엄폐 판정과 최종 평가 집계는 후속 통합에서 연결한다. `EpisodeFinished`의 Aborted 결과는 정상 평가 경기에서 제외하며, 중단한 Agent는 보상 없이 `EpisodeInterrupted()`로 끝낸다.

`Data/duel-ppo.yaml`은 PPO 연결용 초안이다. 128유닛 2층과 10,000스텝 연결 확인 예산을 제안값으로 두었다. 현재 조원 기능과 Python 학습 환경은 연결하지 않았으며 본 학습 예산·시드·평가 조건은 추후 정한다. 300초 경기에서 종료 보상이 늦게 도착하므로 실제 학습에서는 결정 주기와 할인율을 함께 검토한다. 명령·관측 스키마와 사용 설정을 Run ID에 연결해 보관한다.

## 뼈대 검증 결과

Unity 6000.3.28f1에서 자동 검사 15개가 통과했다. EditMode의 관측·행동·종료 정산 검사와 PlayMode 진입 후 Academy 결정 요청, 입력 해제, 연속 리셋 및 경기 중 Agent 비활성화를 검증했다. 실제 게임 전투와 Python 트레이너 연결·성능은 후속 통합에서 확인한다.
