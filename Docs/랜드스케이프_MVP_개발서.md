# 랜드스케이프 MVP 개발서

담당 하종욱 · Unity 6.3 LTS · 2026년 11월 17일 회의 내용 반영

## 1. 개발 결과물과 구조

야외 고정 엄폐물 아레나, 나무·벽·바위, 시작 위치와 중앙 목표, 충돌·가림 판정용 환경, 경기 재설정 및 평가 기록용 맵 정보를 제공한다. PPO 1 vs 1을 우선 지원하고 MA-POCA 3 vs 3은 후속 단계로 둔다.

`고정 시드·설정 → Simplex Noise 높이맵 생성·저장 → 엄폐물·경계 배치 → 스폰·경로 검증 → 경기 준비 완료 → 경기 실행·기록 → 초기 상태 복원` 순서로 구성한다. 경기마다 저장된 같은 지형과 고정 엄폐물을 사용한다.

기준 크기는 Unity 기본 Plane의 X·Z Scale 25 × 25이며, 부모 Scale이 1이면 실제 바닥은 250 × 250 Unity 단위다. 높이 기준은 기본 Cube의 Y Scale 50으로 실제 50 Unity 단위다. 지형의 기준 고도와 실제 기복 범위는 별도로 확정하며, 해당 높이를 모든 지형에 적용한다는 뜻은 아니다. 기존 소형 아레나 목표와 실제 250 × 250 범위의 적합성을 검증한다.

맵은 X·Z 방향으로 각각 5등분하여 총 25개 청크로 구성한다. 부모 Scale 1인 기본 Plane 기준 전체 크기 250 × 250 Unity 단위이므로 각 청크는 50 × 50이다. 청크는 논리적 구분이며 별도 지형 오브젝트나 런타임 로딩을 요구하지 않는다. 기존 회의의 청크 간 한 칸 띄우기 스폰 규칙은 적용 대상과 대각선 판정 합의 후 적용한다.

## 3. 연동 계약

- 이동: 중앙·스폰 위치와 물리 충돌 환경을 제공한다. 캐릭터 반지름·높이·자세·단차 조건을 받아 통로와 스폰을 검증한다. 스폰의 최종 선택·캐릭터 이동은 이동 담당과 연결한다.
- 사격·시야: 엄폐물 및 경계의 차단 레이어를 제공한다. 전방 시야각 오토에임의 대상 선택과 사격 실행은 해당 시스템이 소유한다. 탄약·재장전 연동은 제거한다.
- 상황 판단·학습: 허용 관측, 중앙·엄폐 위치 후보의 사용 방식, 경기 시작·종료·재설정 순서를 합의한다. 마지막 관측 방향과 피격·탄환 단서의 규칙·학습 여부는 미정이다.
- 평가: 맵 버전·엄폐물 ID·경로 ID·시작 조건을 제공한다. 전투 시스템의 사격·피격·사망 사건과 시간을 맞춰 기록한다. 보상 계산은 학습 시스템에서 담당한다.

## 4. 수학·물리 원리와 코드 초안

아래 코드는 문서 검토용이며 프로젝트에 구현하거나 실행한 코드가 아니다. 각 함수는 UnityEngine을 사용하는 클래스 내부에 배치하는 것을 전제로 한다.

### 4.0 고정 지형 생성

높이 샘플마다 여러 주파수의 Simplex Noise 값 N을 가중 평균한다. `s = Σ(aᵢNᵢ) / Σaᵢ`, `h = clamp01((s + 1) / 2)`이며 N은 -1~1 범위를 가정한다. 실제 높이는 기준 높이 + h × 설정 높이 범위다. 주파수·가중치·높이 범위는 소형 맵의 경사와 이동을 확인해 정한다.

생성기 버전, 시드, 해상도와 파라미터를 기록하고 높이맵을 저장한다. Terrain과 TerrainCollider에 동일한 지형 데이터를 적용하며, 스폰 지면·엄폐물 접촉·이동 경로를 생성 이후 검사한다. Simplex Noise 구현체 및 시드 처리 방식은 구현 시 선택·고정한다.

### 4.1 전방 시야각과 가림

정규화한 전방 f와 상대 방향 d의 내적은 두 방향 사이 각도의 코사인이다. 반시야각의 코사인과 비교해 각도 후보를 고른다. 각도 후보 판정 이후 거리·가림·생존·팀 조건을 추가 검사한다.

```csharp
using UnityEngine;

public static class ArenaQueryDraft
{
    // 수평 시야각 후보 검사. 상하 각도 제한은 시야 시스템에서 별도 합의한다.
    public static bool IsInHorizontalCone(Vector3 origin, Vector3 forward,
        Vector3 target, float fullAngleDegrees)
    {
        Vector3 f = Vector3.ProjectOnPlane(forward, Vector3.up);
        Vector3 d = Vector3.ProjectOnPlane(target - origin, Vector3.up);
        if (f.sqrMagnitude < 0.0001f || d.sqrMagnitude < 0.0001f) return false;
        float halfAngle = Mathf.Clamp(fullAngleDegrees, 0f, 360f) * 0.5f;
        return Vector3.Dot(f.normalized, d.normalized) >=
            Mathf.Cos(halfAngle * Mathf.Deg2Rad);
    }

    // blockers에는 엄폐물·벽 등 차단체만 포함한다.
    public static bool IsBlocked(Vector3 origin, Vector3 target, LayerMask blockers)
    {
        return Physics.Linecast(origin, target, blockers, QueryTriggerInteraction.Ignore);
    }
}
```

관측 원점과 총구 원점이 다르면 각 원점에서 검사한다. 검사 시작점이 차단체 내부가 되지 않도록 배치하고, 적 전체가 가려졌는지 일부가 보이는지는 지정된 관측 지점과 판정 규칙으로 결정한다. 한 지점에 대한 선분 검사는 전체 엄폐 활용의 확정 판정이 아니다.

### 4.2 스폰 캡슐 검사

수직 캡슐의 높이 H에는 양 끝 반구가 포함된다. 발 위치 기준 구 중심은 아래쪽 r, 위쪽 H-r이다. 바닥과 장애물 검사를 구분하고 캐릭터 자신은 검사 대상에서 제외한다.

```csharp
public static bool IsSpawnSpaceClear(Vector3 foot, float radius,
    float height, LayerMask obstacles)
{
    if (radius <= 0f || height < 2f * radius) return false;
    Vector3 lower = foot + Vector3.up * radius;
    Vector3 upper = foot + Vector3.up * (height - radius);
    return !Physics.CheckCapsule(lower, upper, radius, obstacles,
        QueryTriggerInteraction.Ignore);
}
```

이 검사는 공간 중첩만 확인한다. 별도 지면 검사로 높이·지지 여부를 확인하고 실제 캐릭터로 중앙 및 엄폐물 사이 접근성을 검사한다. 겹치지 않는 스폰이어도 통로가 막힐 수 있다. 캡슐 반지름·높이는 이동 설정에서 받아 중복 상수화를 피한다.

### 4.3 청크 좌표

맵의 최소 X·Z 좌표를 원점으로 삼고 `floor((월드 좌표 - 원점) / 50)`으로 각 축 인덱스를 구한다. 인덱스는 0~4이며 최대 경계는 범위 밖이다. 맵 크기가 변하면 50 대신 각 축의 전체 크기를 5로 나눈 값을 사용한다. 스폰 위치 선택은 이동 담당 시스템과 연동하며 청크 간격·대각선 규칙은 합의 후 확정한다.

### 4.4 경로와 평가 시간

고정 경로 구역의 진입·이탈 사건에 경로 ID와 시각을 기록한다. 경로 이용 비율은 경기별 선택, 진입 횟수 또는 체류시간 중 집계 단위를 먼저 정한다. 여러 구역이 겹칠 때의 처리와 무진입 경기는 별도로 정의한다.

생존시간은 `사망 또는 종료 시각 - 경기 시작 시각`이다. 배속 학습에서는 벽시계가 아닌 공통 시뮬레이션 시간 또는 스텝을 사용한다. 엄폐 활용 시간 비율을 채택한다면 `유효 엄폐 교전 시간 / 유효 교전 시간`으로 계산하되, 교전·엄폐·동시 상대의 판정과 분모 0 처리를 합의하기 전에는 확정 지표로 산출하지 않는다.

## 5. 경기 재설정과 기록

5분 제한시간은 경기 시스템이 관리한다. 종료 시 승리 +1·패배 -1·무승부 0과 부가 점수는 학습·경기 담당이 정산한다. 시간 초과 시 승패 판정, 보상 항목의 부호·계산식은별도 합의한다. 맵 버전, 생성기 버전·시드·설정과 저장된 지형 및 배치를 고정하고 경기 시작 시 스폰 조합·정책 버전·팀 배치·시간 기준을 기록한다. 위치를 교환할 때도 맵 배치는 유지한다. 환경 검사가 실패하면 경기 시작을 보류하고 원인을 기록한다.

재설정은 경기 실행 정지 → 캐릭터·투사체 등 전투 상태 정리 → 환경 및 기록 상태 복원 → 스폰 검사·배치 → 관측·정책 상태 초기화 → 준비 완료 순서로 담당자와 합의한다. 사망·피해·전투 상태는 각 시스템의 소유자가 초기화한다.

## 6. 단계별 구현과 완료 기준

| 단계 | 작업 | 확인 조건 |
|---|---|---|
| 고정 맵 | 고정 시드 Simplex Noise 지형 생성·저장 및 경계·엄폐물·중앙·스폰 제작 | 동일 생성 설정 재현 및 경기 간 저장된 지형·배치 고정 확인 |
| 공간 검증 | 스폰 중첩·맵 이탈·통로 검사 | 실제 캐릭터가 중앙과 필요한 엄폐 위치에 접근 가능 |
| 1 vs 1 연결 | PPO 환경, 오토에임·사격 가림 연동 | 숨은 적 자동 탐지 방지, 차단체 뒤 사격 판정 확인 |
| 반복 및 기록 | 경기 재설정·시작 위치 교환·사건 연결 | 이전 경기 상태가 남지 않고 동일 조건으로 반복 가능 |
| 후속 확장 | MA-POCA 3 vs 3 검토 | 팀 스폰·통로·평가 조건을 다시 검증 |

첫 확인은 수동 조작 또는 기본 봇으로 진행하고, PPO 학습 결과의 통과 기준은 학습 담당과 정한다. 기본 게임 베이스 목표 기간은 11월 23~29일이며 변경 범위의 세부 일정은 재확정한다.

## 7. 미확정 조건과 후속 확장

실제 전투 영역의 사용 범위·제작 방식·엄폐물 높이·통로 폭·스폰 규칙·제한시간 종료 시 승패 판정·시야각은 담당자와 확정한다. 피킹, 마지막 관측 방향 접근, 피격·근접 탄환 반응과 교착 대응은 규칙 또는 학습 방식이 결정된 뒤 환경 요구를 반영한다.

시간 보상 감소, 대비 생존시간 비율, 엄폐 활용 교전 비율, 어시스트·기여도와 협동 이득의 공통 상대·평가 조건은 미정이다. 협동 지원률은 보류하며 랜드스케이프에서 보상·어시스트를 임의 구현하지 않는다.

고정 맵에서 학습 성능이 빠르게 확보되면 시드를 바꿔 랜덤 지형으로 확장한다. 성능·속도 기준은 팀에서 확정한다. 확장 시 시드별 스폰·엄폐물 배치·충돌·접근성을 검증하고, 학습용과 평가용 시드를 분리하며 경로 분류·재현성·평가 규칙을 다시 설계한다. 고저차 평가와 이동 제약 구역은 후속 검토한다.

## 8. 최신 회의 반영: 지형 충돌과 전투 연동

- 급경사 지형에서 이동 담당과 실제 캐릭터를 사용해 오르막·내리막·경사 경계 및 장애물 접촉 중 지면 꺼짐을 확인한다. 현재 경사 조건을 유지하고, 발생 위치·경사·이동 방향·충돌 설정과 재현 조건을 기록해 원인을 공동 확인한다. 지형과 충돌체의 높이 데이터 및 지면 레이어 일치 여부도 확인한다.
- 야외 나무·벽·바위의 충돌체가 지면에 맞게 배치되고 캐릭터 이동·시야·사격 차단에 의도대로 적용되는지 확인한다. 건물 도입은 미정이며 도입하면 통로·가림·첫 교전 시간과 관련 보상 기준을 함께 재검토한다.
- 캡슐 기준 머리·몸통 판정과 측면 총 배치는 사격 담당과 연결한다. 엄폐물 주변에서 각 부위의 노출과 총구 주변 가림을 검토하며 피격 부위 경계와 부위별 피해량은 확정하지 않는다. 회전 수정의 구체 사양은 이동 담당과 협의한다.
- 경기 시스템의 공통 시간 기준으로 시작·첫 교전·종료 시각과 맵 버전·엄폐물 정보를 연결한다. 무교전 경기와 제한시간 종료를 구분해 기록하며 첫 교전 중앙값의 집계 범위와 무교전 처리 방식은 합의한다.
- 초기 보상 후보는 가한 피해 0.4, 받은 피해 0.4, 회복시간 0.2 - α, 무교전 약 -0.1, 첫 교전 시간 0.2다. 부호·단위·계산식과 회복시간 적용 여부는 미확정이다. 명중률 70~80%의 평가 방식도 검토 중이다. 지형 시스템에서 점수를 지급하지 않는다.

완료 확인: 고정 지형의 급경사 꺼짐 사례를 공동 점검하고, 5분 종료·무승부를 포함한 경기 결과 및 부가 점수 정산은 담당 시스템과 연동하여 확인한다. 나무·벽·바위와 캐릭터의 이동·사격 가림도 확인한다.

## 9. OutdoorArena 엄폐 레이어와 옥상 이동 연동

- OutdoorArena의 모든 오브젝트는 ArenaCover 레이어를 사용한다. 엄폐 분류에는 충돌체의 ArenaWall, ArenaTree, ArenaRock, ArenaBuilding, ArenaBox, ArenaSandbag 태그를 사용하고 언덕은 ArenaTerrain으로 기록한다. 벽 받침과 나무 줄기 충돌체도 부모의 역할 태그를 사용한다.
- ArenaCoverQuery.TryGetOccluder는 관측 위치에서 후보 위치까지 가장 가까운 유효 엄폐 충돌체의 태그를 반환한다. TryGetConcealment는 몸통과 눈의 태그를 각각 반환하며 둘 다 가릴 때 성공한다. 센터, 스폰, 캐릭터, 경계, 사다리 및 편집 표시 대상은 엄폐 집계에 포함하지 않는다.
- 건물 네 채에 `Stairs_01` 사다리와 지면↔옥상의 양방향 `NavMeshLink`가 있다. `NavMeshAgent`와 `ArenaLadderTraversal`을 함께 사용하는 AI에 옥상 목적지를 주면 사다리를 타고 이동한다. 별도의 이동 컨트롤러를 연결할 때는 사다리 이동 중 위치를 동시에 갱신하지 않는다.
- 지형이나 엄폐물의 위치·충돌체를 바꾸면 `Outdoor Arena`의 `NavMeshSurface`를 다시 Bake하고 바닥과 옥상의 연결을 확인한다.
